# Contributing to RepoPacker

Thank you for your interest in contributing to **RepoPacker**. 

RepoPacker is built upon a distinct foundation: **software engineered by AI to format software for AI ingestion.** To preserve the structural identity and core philosophy of the repository, all contributors must adhere to our synthetic-first development model.

---

## 🤖 The AI Mandate (The Synthetic Codebase Rule)

All code contributions to this repository must follow our primary development philosophy:

1. **AI-Generated Foundation:** The vast majority of all contributed source code—including C# backend logic, XAML views, ViewModel commands, converters, and JSON data structures—**must be generated by an artificial intelligence model**.
2. **Human Stewardship & Review:** Human contributors are expected to act as lead architects, prompt engineers, and rigorous reviewers. You are responsible for:
   - Defining problem statements, interface contracts, and architectural guardrails.
   - Steering the model through iterative generation and refinement.
   - Catching edge cases, race conditions, memory leaks, or incorrect API assumptions.
   - Manually fixing compilation issues, missing references, or minor syntax oversights where prompting proves inefficient.
3. **Transparency:** Every pull request must explicitly disclose the model(s) used to generate the code and summarize the prompting process.

Purely hand-written code from scratch is discouraged unless it involves single-line mechanical bug fixes or dependency configuration updates in `.csproj`.

---

## 🛠️ Development Environment & Tech Stack

Ensure your local development environment meets the following specifications before contributing:

- **SDK:** [.NET 10.0 SDK](https://dotnet.microsoft.com/download/dotnet/10.0) or later
- **Language:** C# 13+ / .NET 10 WPF
- **Architecture:** MVVM utilizing `CommunityToolkit.Mvvm`
- **Git Library:** `LibGit2Sharp`
- **Tokenization:** `Microsoft.ML.Tokenizers`
- **OS:** Windows 10 (Build 1809+) or Windows 11

## 📐 Coding Conventions & Style Guidelines

When guiding an AI to generate code for RepoPacker, enforce the following standards:

### 1. Explicit Typing (Strictly No `var`)
To maintain clarity and rigorous type validation across AI code generations, **never use implicit `var` declarations**. All local variables, loop iterators, and resource allocations must state their concrete or interface type explicitly:

```csharp
// Correct
int bufferSize = 65536;
FileInfo fileInfo = new FileInfo(filePath);
List<PackingPreset> presets = new List<PackingPreset>();

// Incorrect
var bufferSize = 65536;
var fileInfo = new FileInfo(filePath);
var presets = new List<PackingPreset>();
```

### 2. MVVM & Separation of Concerns
- Implement all ViewModels using `CommunityToolkit.Mvvm.ComponentModel.ObservableObject`.
- Use source-generator attributes (`[ObservableProperty]`, `[RelayCommand]`, `[NotifyCanExecuteChangedFor]`) to minimize boilerplate.
- Do not place business logic, git operations, or direct file I/O inside code-behind (`MainWindow.xaml.cs`). The code-behind is reserved strictly for window-level visual chrome events (e.g., `WindowChrome` system commands).

### 3. Memory Safety & Large Repositories
- **Streaming Over Buffering:** Never buffer entire file contents or multiple files into large in-memory strings or `StringBuilder` instances. Stream directly via `StreamReader` / `StreamWriter` using fixed-size buffers (e.g., 64 KB `char[]` or `byte[]`) to avoid pushing objects onto the Large Object Heap (LOH).
- **Asynchronous Execution:** All long-running operations (cloning, packing, token counting) must run asynchronously and accept a `CancellationToken` to keep the UI thread responsive.

### 4. GitHub Primer Theming
- Do not hardcode static colors inside XAML elements.
- Bind all brush resources using `{DynamicResource ...}` to ensure compatibility with our multi-theme engine and runtime theme swapping.

## 🚀 Workflow & Submitting a Pull Request

### Step 1: Fork and Branch
1. Fork the repository on GitHub.
2. Clone your fork locally:
   ```bash
   git clone [https://github.com/your-username/RepoPacker.git](https://github.com/your-username/RepoPacker.git)
   cd RepoPacker
   ```
3. Create a descriptive feature branch:
   ```bash
   git checkout -b feature/your-feature-name
   ```

### Step 2: Prompting & Implementation
1. Use the AI model of your choice to draft the solution. Provide the model with the relevant interfaces, models, and constraints outlined in this guide.
2. Review the output critically: inspect threading behavior, asynchronous operations, and compliance with explicit typing rules.
3. Test locally by compiling and packing various public and private repositories.

### Step 3: Pull Request Template
When submitting your PR, include the following disclosure in the description:

```markdown
### Summary
[Brief description of what this PR introduces or fixes]

### AI Generation Disclosure
- **Model(s) Used:** [e.g., Gemini 2.5 Pro, Claude 3.7 Sonnet, GPT-4o]
- **Human Contribution:** [Summarize what was manually inspected, modified, or corrected by you]
- **Prompt Strategy:** [Brief explanation of how the code was requested and steered]

### Verification Checklist
- [ ] Code strictly uses explicit typing (zero `var` usage).
- [ ] Compiles cleanly under .NET 10 without warnings.
- [ ] Follows MVVM using CommunityToolkit.Mvvm.
- [ ] Tested against a sample repository for both dark and light themes.
- [ ] DPAPI encryption and token masking are preserved.
```
